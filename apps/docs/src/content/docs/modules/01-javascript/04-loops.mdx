## Навіщо це QA

Тобі треба перевірити пагінацію: створити 25 користувачів і переконатися, що на другій сторінці їх
рівно 5. Руками — пів години в адмінці. Циклом — три рядки:

```js
for (let i = 1; i <= 25; i++) {
  createUser(`user${i}@example.com`);
}
```

А ось той самий цикл з однією помилкою:

```js
for (let i = 1; i < 25; i++) { /* ... */ } // створить 24 користувачі
```

Тест «на другій сторінці 5 користувачів» падає: їх 4. Ти годину шукаєш баг у пагінації, а він — у
твоєму генераторі даних. Це помилка на одиницю (off-by-one error), і вона найчастіша в циклах.

Цикли в автоматизації всюди: генерація тестових даних, повторні спроби для нестабільного сервісу,
обхід рядків таблиці, пошук першого впалого тесту у звіті.

## Концепція

### `for`

Класичний цикл із лічильником:

```js
for (let i = 0; i < 3; i++) {
  console.log(i); // 0, 1, 2
}
```

Три частини в дужках: **початок** (`let i = 0`), **умова продовження** (`i < 3`) і **крок** (`i++`).
Умова перевіряється перед кожною ітерацією.

Запам'ятай дві звичні форми й не змішуй їх:

- `for (let i = 0; i < n; i++)` — від 0 до n − 1, рівно n разів. Так обходять масиви: індекси починаються з 0.
- `for (let i = 1; i <= n; i++)` — від 1 до n, теж n разів. Зручно для нумерації «user1, user2…».

### `while` і `do...while`

`while` — коли кількість повторень наперед невідома:

```js
let page = 1;
while (hasNextPage(page)) {
  page++;
}
```

`do...while` виконує тіло **хоча б один раз**, а умову перевіряє після:

```js
let response;
do {
  response = fetchStatus();
} while (response === 'pending');
```

### Нескінченні цикли

Якщо умова ніколи не стає хибною, цикл не закінчиться, і тест «зависне» до таймауту:

```js
let attempts = 0;
while (attempts < 3) {
  tryLogin();
  // забули attempts++ → нескінченний цикл
}
```

Правило: у кожного `while` має бути гарантований вихід — лічильник, ліміт спроб або таймаут.

### `break` і `continue`

```js
for (const result of results) {
  if (result.status === 'skipped') {
    continue; // пропустити цю ітерацію, перейти до наступної
  }
  if (result.status === 'failed') {
    break;    // вийти з циклу повністю
  }
  console.log(result.name);
}
```

Усередині функції `return` теж перериває цикл — разом із функцією. Для пошуку «першого такого»
це найпростіший варіант.

### `for...of` проти `for...in`

`for...of` проходить по **значеннях** масиву (і рядка):

```js
const browsers = ['chromium', 'firefox', 'webkit'];
for (const browser of browsers) {
  console.log(browser); // 'chromium', 'firefox', 'webkit'
}
```

`for...in` проходить по **ключах** об'єкта — і для масиву це індекси у вигляді **рядків**:

```js
for (const index in browsers) {
  console.log(index, typeof index); // '0' 'string', '1' 'string', '2' 'string'
}
```

Звідси баги: `index + 1` дає `'01'`, а не `1`. До того ж `for...in` може обійти зайві властивості.
**Для масивів — `for...of` або звичайний `for`. `for...in` — лише для об'єктів** (урок 09).

### Патерн повторної спроби (retry)

Нестабільний сервіс іноді відповідає помилкою, і тест має спробувати ще раз:

```js
let lastError;
for (let attempt = 1; attempt <= 3; attempt++) {
  // спробувати; якщо вийшло — вийти з циклу
  // якщо ні — запам'ятати помилку і спробувати ще раз
}
// жодна спроба не вдалася — повідомити про останню помилку
```

Обмежена кількість спроб — обов'язкова. Retry без ліміту — це нескінченний цикл, який ховає
справжню проблему.

<Aside type="caution" title="Retry не лікує баги">
Повторна спроба — для зовнішньої нестабільності (мережа, повільне середовище). Якщо тест
проходить лише з третьої спроби, бо застосунок поводиться непередбачувано, — це баг, і його треба
завести, а не «загорнути в retry».
</Aside>

<Aside type="tip" title="Що з цього для автотестів">
У Playwright ти рідко писатимеш ручні цикли очікування: `expect(...)` сам повторює перевірку до
таймауту. Але генератори тестових даних, обробку звітів і утиліти фреймворку ти писатимеш саме циклами.
</Aside>

## Типові помилки

1. **Помилка на одиницю** — `<` замість `<=` (або навпаки), початок з 0 замість 1. Перевір першу й
   останню ітерацію та кількість повторень.
2. **Нескінченний цикл** — забутий `i++` у `while` або умова, що ніколи не стає хибною.
3. **`for...in` для масиву** — індекси приходять рядками, а порядок і набір ключів не гарантовані.
4. **Пошук без `break`/`return`** — цикл продовжує роботу й повертає **останній** знайдений елемент
   замість першого.
5. **Retry без ліміту** або retry, що ковтає помилку й повертає `undefined` замість того, щоб
   повідомити про проблему.
6. **Перевірка успіху через truthy** — `if (result)` вважає `0`, `''` і `null` невдачею, хоча функція
   їх успішно повернула.

## Самоперевірка

Відповідай уголос, потім розгорни відповідь.

<details>
<summary>Скільки разів виконається `for (let i = 0; i <= 5; i++)`?</summary>

Шість: для `i` від 0 до 5 включно. Якщо треба рівно п'ять — `i < 5` (від 0) або `i <= 5` (від 1).
</details>

<details>
<summary>Чим `do...while` відрізняється від `while`?</summary>

`do...while` перевіряє умову після тіла, тому виконується хоча б один раз. `while` може не
виконатися жодного разу.
</details>

<details>
<summary>Чому не варто обходити масив через `for...in`?</summary>

`for...in` перебирає ключі, а не значення: для масиву це індекси-рядки (`'0'`, `'1'`). Він також
може обійти додані властивості. Для масивів — `for...of` або `for` з індексом.
</details>

<details>
<summary>Яка різниця між `break` і `continue`?</summary>

`break` повністю виходить із циклу. `continue` пропускає решту поточної ітерації й переходить до
наступної.
</details>

<details>
<summary>Що обов'язково має бути в retry-циклі?</summary>

Ліміт спроб і чітка поведінка наприкінці: якщо жодна спроба не вдалася — повідомити про помилку
(кинути її), а не повернути тихо `undefined`.
</details>
