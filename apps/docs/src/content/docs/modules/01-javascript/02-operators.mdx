## Навіщо це QA

Інтернет-магазин. У кошику три товари по 0,10 грн. Тест перевіряє суму:

```js
const total = 0.1 + 0.1 + 0.1;
console.log(total);          // 0.30000000000000004
console.log(total === 0.3);  // false — тест падає
```

Код магазину правильний, тест — теж. Просто числа з крапкою в JavaScript (і майже в усіх мовах)
зберігаються наближено. Якщо не знати цього, ти або заведеш хибний баг, або — гірше — пропустиш
справжній, коли сайт покаже клієнту «0,30000000000000004 грн».

Друга історія — знижка лояльності:

```js
const discount = user.discountPercent || 5; // «якщо знижки немає — дати 5 %»
```

Користувач, якому менеджер свідомо поставив знижку `0`, отримує 5 %. Бо `0` — falsy, і `||` його
«не бачить». Один символ (`??` замість `||`) — і бага немає.

Оператори — це не арифметика зі школи. Це місця, де дані **непомітно псуються**.

## Концепція

### Арифметика

```js
7 + 2   // 9
7 - 2   // 5
7 * 2   // 14
7 / 2   // 3.5    ← ділення завжди дробове, цілого ділення немає
7 % 2   // 1      ← остача від ділення (remainder)
2 ** 3  // 8      ← піднесення до степеня (exponentiation)
```

`%` знадобиться частіше, ніж здається: «чи парне число» (`n % 2 === 0`), «кожен третій рядок
таблиці», «чи ділиться сума на 5 копійок».

### Скорочені оператори

```js
let attempts = 0;
attempts += 1;   // те саме, що attempts = attempts + 1
attempts++;      // теж +1
let price = 100;
price *= 0.9;    // 90
```

`++` і `--` бувають префіксні (`++x`) і постфіксні (`x++`). Різниця — у тому, **що повертає вираз**:

```js
let a = 1;
const b = a++; // b = 1, a = 2 — спершу повернув старе значення, потім збільшив
let c = 1;
const d = ++c; // d = 2, c = 2 — спершу збільшив, потім повернув
```

Порада: пиши `++` окремим рядком і не використовуй його результат — тоді різниці немає.

### Пастка чисел з плаваючою крапкою

Числа в JavaScript — це формат IEEE 754 (floating point). Дроби на кшталт `0.1` у двійковій системі
нескінченні, тож зберігаються з крихітною похибкою:

```js
0.1 + 0.2            // 0.30000000000000004
0.1 + 0.2 === 0.3    // false
19.99 * 3            // 59.97 ✔ — інколи похибки не видно
1.15 * 100           // 114.99999999999999
```

Як з цим жити, коли йдеться про гроші:

1. **Рахуй у копійках (центах).** Цілі числа до 2⁵³ зберігаються точно:
   ```js
   const priceCents = Math.round(19.99 * 100); // 1999
   const totalCents = priceCents * 3;          // 5997 — точно
   const total = totalCents / 100;             // 59.97
   ```
2. **Округлюй наприкінці через `Math.round`.** `Math.round(x * 100) / 100` — округлення до копійок.
3. **`toFixed` — тільки для показу.** `(0.1 + 0.2).toFixed(2)` повертає **рядок** `'0.30'`.
   Порівнювати його з числом `0.3` через `===` — нова помилка.

<Aside type="caution" title="Округлення через toFixed теж не ідеальне">
`(1.005).toFixed(2)` повертає `'1.00'`, а не `'1.01'`: число `1.005` насправді зберігається як
`1.00499999…`. Саме тому гроші надійніше переводити в цілі копійки.
</Aside>

### Порівняння: числа і рядки

```js
5 > 3          // true
'10' > '9'     // false ← два рядки порівнюються посимвольно: '1' < '9'
'10' > 9       // true  ← рядок і число: рядок перетворюється на число
'abc' > 1      // false ← 'abc' → NaN, а будь-яке порівняння з NaN — false
'Б' > 'А'      // true  ← за кодами символів Unicode
```

Для тестувальника висновок такий: **перш ніж порівнювати значення з UI, перетвори їх на числа**.
Сортування цін `['100', '25', '9']` як рядків дасть хибний порядок — це класичний баг таблиць.

### Логічні оператори `&&`, `||`, `!`

```js
true && false   // false — «і»: обидва мають бути truthy
true || false   // true  — «або»: достатньо одного
!true           // false — «не»
!!'text'        // true  — подвійне заперечення перетворює значення на boolean
```

Важлива деталь: `&&` і `||` повертають **не обов'язково boolean**, а одне з операндів.

```js
'Anna' || 'Гість'   // 'Anna'  — перше truthy
'' || 'Гість'       // 'Гість' — '' falsy, тому друге
null && user.name   // null    — перше falsy, далі не обчислює
```

Це називається обчисленням за короткою схемою (short-circuit evaluation): якщо результат уже відомий,
права частина не виконується.

### `??` проти `||`

Оператор об'єднання з null (nullish coalescing) `??` повертає праву частину **лише** якщо ліва —
`null` або `undefined`. На відміну від `||`, йому байдуже до інших falsy-значень:

```js
0 || 10           // 10  ← 0 вважається «нічим»
0 ?? 10           // 0   ← 0 — нормальне значення
'' || 'Гість'     // 'Гість'
'' ?? 'Гість'     // ''
null ?? 'Гість'   // 'Гість'
```

Як вибирати:

- `??` — коли `0`, `''` або `false` **є валідними значеннями** (кількість, знижка, прапорець).
- `||` — коли порожній рядок теж треба замінити типовим значенням (ім'я для показу в UI).

### Опціональний ланцюжок `?.`

Відповідь API може не містити вкладеного поля. Звичайний доступ до властивості `undefined` падає:

```js
const user = { name: 'Anna' };     // профілю немає
user.profile.city                  // TypeError: Cannot read properties of undefined
user.profile?.city                 // undefined — без помилки
user?.profile?.city ?? 'Не вказано' // 'Не вказано'
```

`?.` зупиняє ланцюжок і повертає `undefined`, якщо ліворуч `null` або `undefined`.
Разом із `??` це стандартний спосіб безпечно прочитати глибоке поле з типовим значенням.

<Aside type="tip" title="Що з цього для автотестів">
Не зловживай `?.` у самих перевірках. Якщо контракт API каже, що `profile` **обов'язковий**, то
`response.profile?.city` сховає баг: тест отримає `undefined` замість чіткого падіння. `?.` — для
полів, які справді можуть бути відсутні.
</Aside>

## Типові помилки

1. **`0.1 + 0.2 === 0.3`** у перевірках сум. Порівнюй копійки (`Math.round(x * 100)`) або округлене
   значення, а не сирі дроби.
2. **`toFixed` для розрахунків** — він повертає рядок. `(10).toFixed(2) + 5` дає `'10.005'`.
3. **`||` для типового значення числа** — `count || 1` перетворює валідний `0` на `1`. Для чисел і
   прапорців — `??`.
4. **Порівняння рядків-чисел** — `'10' < '9'` дорівнює `true`. Спершу `Number(...)`.
5. **`?.` всюди «про всяк випадок»** — ховає `undefined` там, де мала б бути помилка, і баг
   проявляється значно пізніше й далі від причини.
6. **Плутанина `x++` і `++x`** у виразах. Не використовуй результат інкременту — пиши його окремим рядком.

## Самоперевірка

Відповідай уголос, потім розгорни відповідь.

<details>
<summary>Чому `0.1 + 0.2 !== 0.3` і як правильно рахувати гроші?</summary>

Числа зберігаються у двійковому форматі з плаваючою крапкою (IEEE 754), і `0.1` не має точного
двійкового представлення. Гроші рахують у цілих копійках (`Math.round(amount * 100)`), а в гривні
переводять лише для показу.
</details>

<details>
<summary>Що поверне `'' || 'Гість'` і `'' ?? 'Гість'`? Чому по-різному?</summary>

`'Гість'` і `''`. `||` бере праву частину для будь-якого falsy-значення, `??` — лише для `null` і
`undefined`.
</details>

<details>
<summary>Чому `'10' > '9'` дорівнює `false`?</summary>

Обидва операнди — рядки, тому вони порівнюються посимвольно, як у словнику: `'1'` менше за `'9'`.
Числа треба спершу перетворити через `Number()`.
</details>

<details>
<summary>Що робить `user?.address?.city` і коли його не варто використовувати в тестах?</summary>

Повертає `undefined` замість помилки, якщо `user` або `address` — `null`/`undefined`. У перевірках
обов'язкових полів його краще уникати: він ховає порушення контракту API.
</details>

<details>
<summary>Чому `toFixed(2)` не підходить для розрахунків?</summary>

Він повертає рядок, а не число. Додавання до рядка склеює його, а `===` з числом завжди дає `false`.
`toFixed` — для форматування тексту на екрані.
</details>
