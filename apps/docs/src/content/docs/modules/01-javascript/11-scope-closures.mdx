## Навіщо це QA

Тестам потрібні унікальні дані: `user-1@test.dev`, `user-2@test.dev`… Перша спроба зазвичай така:

```js
let counter = 0; // глобальна змінна на весь файл

function nextEmail() {
  counter++;
  return `user-${counter}@test.dev`;
}
```

Працює, доки тест один. Потім з'являється другий генератор — для замовлень — і хтось «для зручності»
використовує той самий `counter`. Або інший тест скидає `counter = 0` посеред прогону, і два тести
реєструють однаковий email. Бекенд відповідає `409 Conflict`, тест падає, а запускаєш окремо —
зелений. Класичний нестабільний (flaky) тест через **спільний змінний стан**.

Замикання розв'язують це: кожен генератор має **власний** лічильник, до якого ніхто ззовні не
дотягнеться. Цей патерн ти побачиш у фікстурах Playwright, фабриках тестових даних і будь-якому
колбеку. А на співбесіді питання «що таке замикання?» — одне з найчастіших.

## Концепція

### Область видимості (scope)

**Область видимості** — це частина коду, де змінна доступна. У JavaScript їх три рівні:

```js
const env = 'staging';           // глобальна (global scope): видно всюди у файлі

function login() {
  const token = 'abc';           // функційна (function scope): видно лише всередині login
  if (env === 'staging') {
    const debug = true;          // блокова (block scope): видно лише всередині { }
    console.log(env, token, debug); // усе видно
  }
  console.log(debug);            // ReferenceError: debug is not defined
}

console.log(token);              // ReferenceError: token is not defined
```

Правило просте: **зсередини видно назовні, ззовні всередину — ні**. Блок — це будь-які фігурні
дужки: `if`, `for`, `while` або просто `{ }`.

### `let` і `const` проти `var`

`let` і `const` живуть у **блоці**. Застарілий `var` блоків не помічає — лише функції:

```js
if (true) {
  var a = 1;
  let b = 2;
}
console.log(a); // 1 — var «протік» з блоку
console.log(b); // ReferenceError
```

Найвідоміший наслідок — баг із циклом і таймером:

```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 4, 4, 4 — одна змінна i на всі ітерації, і на момент виклику вона вже 4

for (let i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 1, 2, 3 — let створює нову i для кожної ітерації
```

Чому колбек виконується пізніше, розберемо в модулі 02 «Асинхронний JavaScript». Поки запам'ятай:
з `let` цього бага не буває. Ще одна причина ніколи не писати `var`.

### Затінення (shadowing)

Якщо всередині оголосити змінну з тим самим ім'ям, що й зовні, внутрішня **затінює** зовнішню:

```js
const user = 'admin';

function createOrder() {
  const user = 'guest';   // інша змінна з тим самим ім'ям
  return user;            // 'guest'
}

console.log(user);        // 'admin' — зовнішня не змінилася
```

Це не помилка, але читати такий код важко: «а який тут `user`?». Давай змінним різні імена.

### Лексичне оточення (lexical environment)

Функція «бачить» змінні з того місця, **де її написали** в коді, а не звідки її викликали.
Кожен виклик функції створює нове **лексичне оточення** — «коробку» з її локальними змінними та
посиланням на зовнішню коробку. Коли рушій шукає змінну, він іде цим ланцюжком назовні аж до
глобальної області.

```js
const baseUrl = 'https://shop.test';

function buildUrl(path) {
  return `${baseUrl}${path}`; // baseUrl знайдено у зовнішньому оточенні
}
```

### Замикання (closure)

А тепер головне. Функція, створена всередині іншої функції, **пам'ятає** оточення, у якому
народилася, навіть після того, як зовнішня функція завершилася. Це і є **замикання**.

```js
function createCounter() {
  let count = 0;              // живе в оточенні конкретного виклику createCounter

  return function () {
    count++;                  // внутрішня функція «замкнула» count
    return count;
  };
}

const next = createCounter();
next(); // 1
next(); // 2

const other = createCounter(); // НОВИЙ виклик → нове оточення → свій count
other(); // 1
next();  // 3 — лічильники незалежні
```

Дві ключові думки:

1. `count` не зник після `return` — його тримає внутрішня функція.
2. **Кожен виклик** `createCounter()` створює окремий `count`. Тому генератори не заважають один одному.

### Де замикання працюють у тестах

**Приватний стан.** До `count` ззовні не дістатися — лише через функції, які ти повернув:

```js
function createSession() {
  let token = null;
  return {
    login: (value) => { token = value; },
    isLoggedIn: () => token !== null,
  };
}
```

Об'єкт із кількома функціями, що ділять одну замкнену змінну, — звичайна «фабрика» (factory function).

**`once`** — обгортка, що дозволяє виконати дію лише один раз (наприклад, підготувати тестову базу):

```js
function once(fn) {
  let called = false;
  let result;
  return (...args) => {
    if (!called) {
      called = true;
      result = fn(...args);
    }
    return result;
  };
}
```

**Мемоізація (memoize)** — запам'ятовування результатів «дорогої» функції, щоб не рахувати двічі.
Ключ — аргумент, значення — результат; кеш живе в замиканні:

```js
function memoize(fn) {
  const cache = {};
  return (key) => {
    if (!Object.hasOwn(cache, key)) {
      cache[key] = fn(key);
    }
    return cache[key];
  };
}
```

<Aside type="tip" title="Що з цього для автотестів">
У модулі 02 ти напишеш функцію очікування (polling), яка в замиканні пам'ятає час старту й кількість
спроб. А в Playwright кожен колбек `test('...', async ({ page }) => { ... })` — теж замикання: він
бачить змінні файлу, у якому написаний.
</Aside>

## Типові помилки

1. **Спільний лічильник на рівні файлу.** Глобальна `let counter` змінюється з будь-якого місця —
   тести починають залежати від порядку запуску. Ховай стан у замикання.
2. **`var` у циклі з колбеком.** Усі колбеки бачать одну й ту саму змінну з останнім значенням.
   Пиши `let`.
3. **Стан оголошено всередині внутрішньої функції.** Тоді він створюється заново на кожному виклику:
   ```js
   function createCounter() {
     return () => {
       let count = 0; // щоразу з нуля — завжди поверне 1
       return ++count;
     };
   }
   ```
   Змінна стану має жити у **зовнішній** функції.
4. **Очікування, що два генератори поділять лічильник.** Не поділять — і це добре. Кожен виклик
   фабрики дає новий, незалежний стан.
5. **Затінення «випадково».** Внутрішня змінна з тим самим ім'ям приховує зовнішню, і ти змінюєш не те,
   що думаєш. Лінтер (ESLint, правило `no-shadow`) попередить про це.

## Самоперевірка

Відповідай уголос, потім розгорни відповідь.

<details>
<summary>Що таке замикання одним реченням?</summary>

Це функція разом із лексичним оточенням, у якому її створили: вона має доступ до змінних зовнішньої
функції навіть після того, як та завершилася.
</details>

<details>
<summary>Чому два виклики `createCounter()` дають незалежні лічильники?</summary>

Кожен виклик функції створює нове лексичне оточення з власною змінною `count`. Повернена функція
замикає саме «своє» оточення.
</details>

<details>
<summary>Чому цикл з `var` і `setTimeout` друкує `4, 4, 4`?</summary>

`var` має функційну область видимості, тож на весь цикл є одна змінна `i`. Колбеки виконуються після
циклу, коли `i` вже дорівнює 4. З `let` кожна ітерація отримує свою копію `i`.
</details>

<details>
<summary>Чим погана глобальна змінна-лічильник у тестових даних?</summary>

Її може змінити будь-який код, тож тести починають впливати один на одного й залежати від порядку
запуску. Замикання ховає стан: змінити його можна лише через функції, які ти явно надав.
</details>

<details>
<summary>Що таке затінення і чим воно небезпечне?</summary>

Внутрішня змінна з тим самим ім'ям приховує зовнішню. Код працює, але легко переплутати, яку змінну
ти читаєш чи змінюєш.
</details>
