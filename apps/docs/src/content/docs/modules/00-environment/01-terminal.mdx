## Навіщо це QA

Ранок, CI-пайплайн упав. У звіті — 300 рядків логу. Колега-автоматизатор за 10 секунд пише:

```sh
grep ERROR logs/app.log | tail -5
```

і бачить п'ять останніх помилок. Ти тим часом гортаєш лог мишкою.

Термінал (terminal, command line) — робоче місце автоматизатора. Тести запускаються командою
(`npx playwright test`), CI — це просто сервер, який виконує команди термінала, а логи, Docker і Git
живуть саме тут. Мишкою в CI не клікнеш.

## Концепція

### Термінал і shell

**Термінал** — вікно, куди ти вводиш команди. **Shell** (оболонка) — програма, яка їх виконує.
У курсі ми використовуємо **bash**-сумісні команди: вони однакові в CI (Linux), на macOS (zsh) і в
Windows через **Git Bash**, що встановлюється разом із Git.

<Aside type="caution" title="Windows: обери Git Bash">
PowerShell і `cmd` мають інші команди (`dir` замість `ls`, `del` замість `rm`). Щоб не вчити все двічі,
у VS Code зроби Git Bash терміналом за замовчуванням — як саме, описано в уроці
[VS Code для автоматизатора](/modules/00-environment/03-vscode/).
</Aside>

Команда складається з імені, прапорців (options, flags) і аргументів:

```sh
ls -la tests/
#  │  │   └── аргумент: що показати
#  │  └────── прапорці: -l (детально) + -a (разом із прихованими)
#  └───────── команда
```

### Де я: навігація

```sh
pwd              # print working directory — де я зараз
ls               # що тут лежить
ls -la           # детально, разом із прихованими файлами (.env, .gitignore)
cd tests         # перейти в теку tests
cd ..            # на рівень вище
cd ~             # у домашню теку
cd -             # повернутися туди, де був
```

Шляхи бувають **відносні** (`tests/e2e` — від поточної теки) і **абсолютні** (`/home/ann/project`,
`/c/Users/ann` у Git Bash). У скриптах і конфігах майже завжди потрібні відносні: на іншому комп'ютері
й у CI абсолютний шлях буде іншим.

`.` — поточна тека, `..` — батьківська.

### Створення

```sh
mkdir reports                 # створити теку
mkdir -p tests/e2e/auth       # -p: разом з усіма проміжними теками, без помилки, якщо вже є
touch tests/e2e/login.spec.ts # створити порожній файл
```

### Копіювання, переміщення, видалення

```sh
cp fixtures/user.json backup.json   # копіювати файл
cp -r fixtures fixtures-old         # копіювати теку: -r (recursive)
mv old.txt new.txt                  # перейменувати
mv report.html reports/             # перемістити
mv notes.txt docs/README.md         # перемістити й перейменувати одночасно
rm report.html                      # видалити файл
rm -r test-results                  # видалити теку з усім вмістом
```

<Aside type="danger" title="Кошика немає">
`rm` видаляє назавжди і нічого не перепитує. Перед `rm -r` подивись `pwd` і `ls`. Ніколи не запускай
`rm -rf` зі змінною, яка може бути порожньою, і з `/` чи `~` у шляху.
</Aside>

### Читання і пошук

```sh
cat package.json          # показати весь файл
head -20 logs/app.log     # перші 20 рядків
tail -20 logs/app.log     # останні 20
tail -f logs/app.log      # стежити за файлом наживо (вихід — Ctrl+C)
grep ERROR logs/app.log   # рядки, що містять ERROR
grep -i error logs/app.log   # без урахування регістру
grep -n ERROR logs/app.log   # з номерами рядків
grep -r "baseURL" tests/     # шукати рекурсивно по теці
```

У `grep` ще багато корисних прапорців — один із них знадобиться в каті. Список: `grep --help`.

### Перенаправлення

Вивід команди можна записати у файл замість екрана:

```sh
echo "node_modules/" > .gitignore   # > створює або ПЕРЕЗАПИСУЄ файл
echo ".env" >> .gitignore           # >> ДОПИСУЄ в кінець
npx playwright test > run.log 2>&1  # 2>&1: помилки (stderr) — туди ж, куди й звичайний вивід
```

### Конвеєри (pipes)

`|` передає вивід однієї команди на вхід наступній. Так з маленьких команд збирають потужні:

```sh
grep ERROR logs/app.log | tail -5          # п'ять останніх помилок
grep ERROR logs/app.log | grep -v timeout  # помилки, крім таймаутів (-v — інвертувати)
ls tests/e2e | wc -l                       # скільки файлів у теці
```

### Прийоми, що заощаджують години

- **Tab** — автодоповнення імен файлів і команд. Натискай постійно: менше друкарських помилок.
- **↑ / ↓** — історія команд. `Ctrl+R` — пошук в історії.
- **Ctrl+C** — перервати команду, що зависла або працює вічно.
- `команда --help` або `man команда` — довідка прямо в терміналі.
- `clear` або `Ctrl+L` — очистити екран.

## Типові помилки

1. **Команда виконується «не там».** `npm run check` у теці `exercises/` замість кореня проєкту —
   і npm не знаходить скрипт. Перш ніж запускати, дивись `pwd`.
2. **Пробіли в шляхах без лапок.** `cd My Tests` — це `cd` з двома аргументами. Правильно:
   `cd "My Tests"`. А краще — не використовуй пробіли в іменах тек проєкту взагалі.
3. **`>` замість `>>`.** Хотів дописати рядок у `.gitignore` — а перезаписав файл.
4. **`mv` замість `cp`.** Оригінал зник, а ним користувалися інші тести.
5. **Абсолютні шляхи в скриптах.** `/Users/ann/project/fixtures` працює лише на ноутбуці Ані.
6. **PowerShell-команди в bash і навпаки.** Якщо бачиш `command not found` — перевір, у якому ти shell.

## Практика

Ката: `exercises/00-environment/01-terminal`. Ти розкладаєш файли проєкту по теках, прибираєш сміття
і рахуєш помилки в лозі — як у перший день на реальному проєкті.

1. Створи собі тимчасову теку для експериментів і пройди всі шість завдань **руками**, перевіряючи
   результат через `ls` і `cat`.
2. Запиши команди у файл `exercises/00-environment/01-terminal/commands.sh`.
3. Запусти перевірку з кореня репозиторію:

   ```sh
   npm run check -- exercises/00-environment/01-terminal
   ```

Тест виконує твій скрипт у тимчасовій теці, тож твої файли в репозиторії він не зачепить.

Вправи лежать у репозиторії курсу на твоєму комп'ютері, а не на сайті.
Ще не налаштував — див. [Де лежать вправи і як їх запустити](/start-here/how-to-learn/#де-лежать-вправи-і-як-їх-запустити).

## Самоперевірка

<details>
<summary>Чим відрізняються відносний і абсолютний шляхи? Що з них писати в скриптах тестів?</summary>

Відносний рахується від поточної теки (`tests/e2e`), абсолютний — від кореня диска (`/home/ann/...`).
У скриптах — відносні: абсолютний шлях на іншій машині чи в CI буде іншим.
</details>

<details>
<summary>Чим `>` відрізняється від `>>`?</summary>

`>` створює файл або перезаписує його, `>>` дописує в кінець.
</details>

<details>
<summary>Як вивести лише рядки з помилками з останніх 100 рядків логу?</summary>

`tail -100 logs/app.log | grep ERROR` — конвеєр передає вивід `tail` на вхід `grep`.
</details>

<details>
<summary>Як видалити теку з вмістом і чому з цією командою треба бути обережним?</summary>

`rm -r тека`. Видалення остаточне — кошика немає, підтвердження не буде. Перевір `pwd` і шлях.
</details>
