Привіт. Я поясню, як влаштований цей курс і чому саме так. Прочитай цю сторінку повністю —
вона заощадить тобі тижні.

## Головна ідея

Інформації про JavaScript і Playwright у світі більше, ніж достатньо. Людей зупиняє не її брак, а три речі:

1. **Немає порядку.** Незрозуміло, що вчити спочатку і що з цього справді знадобиться в автоматизації.
2. **Немає перевірки.** Прочитав статтю — здається, що зрозумів. Сів писати — порожній екран.
3. **Немає зв'язку.** Знання лишаються окремими шматками і не складаються в робочий інструмент.

Тому тут кожна тема має **причину** (навіщо це QA), **практику** (ката з перевіркою) і **місце**
в твоєму фінальному фреймворку.

## Як влаштований кожен урок

| Розділ | Що там |

| **Практика** | Ката з автоматичною перевіркою |
| **Самоперевірка** | Питання, на які варто відповісти вголос, перш ніж іти далі |
| **Співбесіда** | Як цю тему питають на інтерв'ю — українською та англійською |

## Де лежать вправи і як їх запустити

Сайт — це підручник. Вправи (ката, від япон. *kata* — «форма»: коротка вправа, яку повторюють до
автоматизму) лежать **не на сайті, а в репозиторії курсу на твоєму комп'ютері**. Ти розв'язуєш їх у
редакторі коду, а перевіряєш командою в терміналі.

Один раз підготуй робоче місце. Якщо якісь слова тут незнайомі — нічого страшного: модуль
[00 «Середовище розробника»](/modules/00-environment/) пояснює кожен крок детально. Поки просто
повтори команди.

<Steps>

1. Встанови [Node.js](https://nodejs.org/) версії 22 або новішої (LTS), [Git](https://git-scm.com/downloads)
   і [VS Code](https://code.visualstudio.com/).

2. Відкрий термінал (на Windows — **Git Bash**, на macOS — **Terminal**) і завантаж курс:

   ```sh
   git clone https://github.com/DanielKuka/qa-academy.git
   cd qa-academy
   npm install
   ```

3. Відкрий теку `qa-academy` у VS Code: **File → Open Folder**. Термінал усередині редактора —
   **Terminal → New Terminal**. Усі команди курсу запускаються з цієї теки (кореня репозиторію).

</Steps>

<Aside type="tip" title="Свій fork — краще">
Щоб зберігати власні рішення на GitHub і отримувати оновлення курсу, працюй у своєму **fork** —
як його зробити, пояснює урок [GitHub: репозиторій, fork, pull request](/modules/00-environment/05-github/).
Для старту вистачить і простого `git clone`.
</Aside>

## Як працює практика

Усі вправи лежать у теці `exercises/` репозиторію. Кожна ката — це файл із завданнями та тести, які
перевіряють твоє рішення.

<Steps>

1. Відкрий файл `exercise.js` вправи і прочитай коментарі `TODO`.

2. Запусти перевірку саме цієї вправи:

   ```sh
   npm run check -- exercises/01-javascript/01-variables-types
   ```

3. Червоні тести — це нормально. Читай повідомлення: кожне з них — підказка від мене.

4. Пиши код, доки все не стане зеленим. Для зручності є режим спостереження:

   ```sh
   npm run check:watch -- exercises/01-javascript/01-variables-types
   ```

</Steps>

Поруч із кожною вправою є тека `solution/`. **Не відкривай її, поки не розв'яжеш сам** або поки не
застрягнеш більше ніж на годину. Порівняти своє рішення з еталонним після — дуже корисно.

<Aside type="tip" title="Правило 20 хвилин">
Застряг — шукай самостійно 20 хвилин (документація, повідомлення помилки, `console.log`). Не вийшло —
питай ментора. Менше 20 хвилин — ти не тренуєш навичку пошуку. Більше години — ти просто втрачаєш час.
</Aside>

## «Я це вже знаю»: пропуск тем

Ти не зобов'язаний проходити заново те, що вже вмієш.

- **Урок** можна позначити як «вже знаю» кнопкою внизу сторінки уроку. Порада: спершу розв'яжи кату.
  Пройшла з першої спроби — пропускай сміливо.
- **Модуль** цілком можна пропустити на його сторінці-огляді, але тільки після самоперевірки: ти
  чесно підтверджуєш кожну контрольну навичку модуля.

Позначки зберігаються в твоєму браузері. На сторінці [Мій прогрес](/progress/) їх можна
експортувати у файл і перенести на інший комп'ютер.

## Фінальний проєкт росте разом з тобою

З першого модуля ти пишеш код, який потім стане частиною твого фреймворку: генератори тестових даних,
утиліти очікування, типи для API, Page Objects, фікстури, CI. Наприкінці курсу (модуль 13) ти збираєш
усе в публічний репозиторій на GitHub — це твоє портфоліо.

## Ритм

- **Регулярність важливіша за обсяг.** Година щодня дає більше, ніж сім годин у неділю.
- **Код пиши руками.** Не копіюй приклади — передруковуй і змінюй. Так пальці й голова запам'ятовують.
- **Повертайся до старого.** Перед новим модулем пробіжись по питаннях самоперевірки попереднього.
- **Пояснюй уголос.** Якщо не можеш пояснити тему за дві хвилини — ти її ще не знаєш. Це і є
  тренування до співбесіди.
